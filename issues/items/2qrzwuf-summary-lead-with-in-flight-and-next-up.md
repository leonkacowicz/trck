# summary: lead with in-flight and next-up

## Summary
The file opens with a counts table and then 190 lines of hierarchy. Nothing in it says what is being
worked on or what to pick up next, although the engine computes exactly that — `ready`/`next` rank
the actionable leaves by demand cone, and `list --status in-progress,in-review` is the in-flight set.

Two sections at the top:

    ## In flight
    - [#6ezbd38][6ezbd38] ready: only offer work nobody has started — 80% `tracker-features`
    - [#u5fc5vm][u5fc5vm] trck diff: semantic diff of tracker state between revisions — 29%

    ## Next up
    - [#38qfknm][38qfknm] restore the coverage the deleted suite carried: hooks, setup-git, …
    - [#35qkx68][35qkx68] install: Windows has assets but no working install path

Plus a one-line header replacing the counts table:

    **46 backlog · 4 in-progress · 0 in-review · 182 done** — 232 issues, 78% complete by points

## Two decisions this forces
- **Churn.** Pulling in the demand ranking means `SUMMARY.md` changes whenever the ranking shifts —
  which is on every status change anywhere in the graph, not only on edits to the issues shown. The
  file is regenerated by every mutating verb either way, so this is about diff noise in review, not
  about extra writes. Capping "Next up" at a handful of rows bounds it; it does not remove it.
- **Overlap.** An in-progress epic belongs in both "In flight" and the open-work section. Either "In
  flight" lists only leaves, or the open-work section skips what is already in flight. Pick one and
  say which in the generated file, or the reader will think it is a bug.

## Acceptance criteria
- [ ] "In flight" lists non-terminal, non-backlog rows; "Next up" lists the top N by the same ranking
      `ready` uses, sharing that code rather than re-deriving it.
- [ ] The overlap rule above is chosen and documented in one line in the generated output.
- [ ] N is a constant in `src/config.rs` beside the rest of the fixed vocabulary, not a flag —
      `summary` takes no options today and should not grow one for this.
- [ ] Empty sections render as `_none_`, matching the existing status sections.
- [ ] Conformance fixture with an in-progress epic, an in-review leaf, and a blocked backlog row that
      must **not** appear under "Next up".

## Notes
- `Graph::ranked_ready` in `src/graph.rs` is the ranking; `cmd_ready` in `src/query/mod.rs` is the
  existing caller to copy the call shape from.
- The `↑<priority>(#id)` demand marker `ready` prints is probably worth carrying over — it is what
  makes a low-priority row at the top read as deliberate rather than broken.
