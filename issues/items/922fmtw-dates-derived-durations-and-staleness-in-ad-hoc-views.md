# dates: derived durations and staleness in ad-hoc views

## Summary
Every row already carries `created`, `started` and `closed`, so age, lead time (`created`→`closed`)
and cycle time (`started`→`closed`) are all derivable **today, with no schema change**. Nothing in
the engine computes or shows them. This epic makes those durations visible where they help you
decide what to work on.

The governing constraint: these values depend on *now*, so they must stay out of anything
generated and committed. `SUMMARY.md` is regenerated by every mutating verb and lives in git — an
age column there would rewrite the file on every run and churn the diff forever. Durations belong
to ad-hoc terminal output only (`show`, `list`, `ready`), never to a generated artifact.

Scope is deliberately limited to what the three stored timestamps can answer. Time spent in an
intermediate status (how long did this sit in `in-review`?) is **not** derivable from them and is
out of scope — see [[gybeetp]].

## Acceptance criteria
- [ ] Durations are computed in one place and reused by every view that shows them.
- [ ] No generated artifact (`SUMMARY.md`, `index.jsonl`) gains a now-dependent value.
- [ ] Children done.
